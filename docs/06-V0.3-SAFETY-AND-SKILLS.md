# KatAI v0.3.0 — Safety Engine & KatLearn Skills Specification

> Status: **Approved direction / implementation pending**  
> Scope: KatAI service and its integration contract with KatLearn.  
> This document is a technical specification, not evidence that the features have been implemented or tested.

## 1. Product boundaries

KatAI remains an independently trained, bilingual (English/Vietnamese), local-first English-learning system. Do not add Gemini or another hosted chatbot as a hidden generation fallback.

The supported learning domain is English. For requests outside the supported domain, the scope layer returns exactly:

`Hiện tại, chúng tôi không hỗ trợ các môn học khác ngoài Tiếng Anh. Xin cảm ơn`

KatWork and the other learning skills are internal capabilities routed by KatAI. They are not separate user-facing products or standalone tabs.

## 2. Target architecture

```text
KatLearn — PHÒNG HỌC AI
        |
Authenticated KatLearn API
        |
KatAI API boundary
        |
Input normalization + request validation
        |
Independent Safety / Scope Engine
        |
Skill Router + per-skill permission checks
        |
  +-----+----------+-----------+----------------+
  |                |           |                |
KatAI Core      KatWork    KatGames       Learning Skills
  |                |           |                |
  +----------------+-----------+----------------+
        |
Output validation + response schema validation
        |

        |

```

The Safety Engine must run before model inference and again before tool execution/output delivery. The model must never be able to override policy decisions or grant itself permissions.

## 3. Safety Engine v2 requirements

### 3.1 Request handling pipeline

1. Normalize Unicode and whitespace; enforce request size and schema limits.
2. Classify the request intent and determine whether it belongs to English learning.
3. Detect policy violations and prompt-injection attempts using layered checks, not a keyword list alone.
4. Apply a deterministic policy decision: allow, deny, or request clarification.
5. Route only allowed requests to a skill with the minimum required permissions.
6. Validate tool output and generated content before returning it.
7. Record minimal security telemetry without storing unnecessary learner content.

### 3.2 Required protections

- Treat user text, retrieved content, uploaded material, and tool output as untrusted data.
- Keep system policy separate from user instructions and tool-returned content.
- Never execute instructions embedded in a worksheet, passage, or retrieved document.
- Deny arbitrary shell, filesystem, network, secret, and administrative access.
- Require authenticated, server-side authorization for learner-specific records.
- Validate every tool argument against a strict schema and enforce timeouts and output-size limits.
- Apply per-user rate limits and request quotas at the API boundary.
- Prevent cross-user access by deriving identity from the authenticated session, never from a user-supplied `user_id`.
- Do not expose hidden prompts, credentials, environment variables, or internal policy text.
- Provide a safe fallback for ambiguous or unsupported requests.
- Add regression tests for false positives, false negatives, prompt injection, malformed inputs, and tool permission boundaries.

### 3.3 Safety decision contract

Use explicit decisions such as `allow`, `deny`, and `clarify`, with a machine-readable reason code. Do not leak sensitive policy internals to the learner. Safety rules must be versioned and tested independently from model weights.

## 4. KatWork — quiz skill inside PHÒNG HỌC AI

KatWork is a backend skill invoked when a learner asks KatAI in KatLearn's **PHÒNG HỌC AI** to create a multiple-choice quiz. It does not create a separate tab or standalone application.

Example request: "Tạo 10 câu trắc nghiệm về Present Perfect."

Workflow:

1. KatAI identifies quiz-generation intent and extracts topic, level, count, language, and constraints.
2. Skill Router invokes KatWork.
3. KatWork generates questions and plausible distractors.
4. A separate validator checks the stem, every option, the answer key, explanation, ambiguity, and duplicate coverage.
5. KatLearn Quiz Adapter converts the validated pack into the exact schema expected by the existing quiz UI.
6. PHÒNG HỌC AI displays the quiz; KatLearn handles answer selection, scoring, and learner-facing interaction.

Initial supported question types:
- Single-answer multiple choice.
- Multiple-answer questions only when explicitly requested and supported by the UI.
- True/false only when requested or enabled by the quiz configuration.

Every question must be self-contained, unambiguous, and answerable from the supplied lesson content or established English-language knowledge. If a user asks for a quiz based on a specific Unit, passage, or uploaded file, KatWork must use that supplied source and must not invent missing textbook content.

Suggested internal question schema:

```json
{
  "id": "q001",
  "type": "single_select",
  "topic": "Present Perfect",
  "difficulty": "intermediate",
  "question": "She _____ here since 2020.",
  "options": [
    {"value": "A", "label": "lives"},
    {"value": "B", "label": "lived"},
    {"value": "C", "label": "has lived"},
    {"value": "D", "label": "is living"}
  ],
  "correct_values": ["C"],
  "explanation": "The present perfect connects a past starting point to the present.",
  "validation_status": "pending"
}
```

The schema above is an internal example. The adapter must match KatLearn's actual quiz contract before integration. A generated answer key must not be marked verified until it passes independent validation. Invalid or uncertain items must be regenerated or omitted, not silently published.

KatWork capabilities:
- Custom quiz by topic and requested count.
- Vocabulary and grammar quizzes.
- Unit review, when trusted Unit content is available.
- Reading-comprehension quizzes, when the passage is supplied or from an approved source.
- Difficulty selection.
- Explanations and quiz regeneration.
- Quiz history only through KatLearn's authenticated persistence layer.

## 5. KatGames — game progress skill

KatGames is a backend skill for reading and summarizing supported game progress data. It must not replace the game engine or independently award points.

Capabilities:
- Read session history, scores, accuracy, and reaction-time metrics exposed by KatLearn.
- Summarize progress and trends.
- Suggest an appropriate next practice level without forcing progression.
- Identify missing or inconsistent records for review.

Hard boundaries:
- Never modify KatCoin balances, formulas, synchronization, rewards, or authoritative game scores.
- Never trust a client-supplied user identifier or score.
- Never write progress unless a separately authorized KatLearn endpoint explicitly supports that operation.
- Default to read-only access.
- Do not infer health, attention disorders, or personal traits from reaction-time statistics.

Each skill must declare: input schema, output schema, required permissions, data sources, timeout, resource limits, and tests.

## 7. KatLearn integration contract

- KatWork is invoked from the existing PHÒNG HỌC AI chat flow.
- KatLearn remains responsible for rendering quiz UI, recording answers, and calculating scores.
- KatGames reads progress through authenticated, server-side endpoints.
- No skill accesses the KatLearn database directly.
- Do not modify unrelated LMS behavior, existing coin synchronization, or game scoring formulas.
- Confirm actual KatLearn API and quiz schemas before writing the adapter; do not guess endpoint names or fields.
- Use per-user authorization and test cross-account isolation.

## 8. Acceptance tests before release

### Safety
- Out-of-scope requests receive the exact fixed response.
- Prompt-injection text inside a passage cannot change system policy.
- A skill cannot call another skill or access data without permission.
- Malformed and oversized requests are rejected safely.
- User A cannot read User B's quiz history or game progress.
- Secret and internal configuration values never appear in responses.

### KatWork
- Requested question count and topic are preserved.
- Every single-select question has exactly one correct option.
- All distractors are checked for accidental correctness.
- Answer keys and explanations agree.
- Source-based quizzes do not invent facts absent from the source.
- Invalid questions are blocked from publication.
- Output matches the real KatLearn quiz schema.

### KatGames
- Progress summaries match authoritative KatLearn records.
- Read-only operations do not mutate scores or coins.
- Client-supplied user IDs cannot access another learner's records.
- Missing metrics are reported as unavailable, not fabricated.

### Release gate
Do not label v0.3.0 production-ready until implementation, automated tests, security review, and integration tests have actually passed. Report test results and known limitations honestly.
